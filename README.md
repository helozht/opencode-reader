# OpenCode Reader

一个本地运行的 OpenCode 会话阅读器。直接读取 OpenCode 的 SQLite 数据库，以类似“文件管理器 + Markdown 阅读器”的界面浏览历史会话，并支持对目录树、单个会话以及全库内容进行搜索。

程序只读取数据库，不会修改 OpenCode 的任何数据。

## 功能

- **目录树浏览**
  - 按会话的 `directory` 字段组织为目录树。
  - 只显示包含会话的目录，以及这些目录下的会话。
  - 目录显示会话数量，会话按最后更新时间排序。
  - 支持子代理会话标记和目录展开/折叠。

- **会话阅读**
  - 渲染用户与助手的完整对话。
  - 支持 Markdown、代码块、表格、列表、链接等。
  - 折叠展示思考过程和工具调用。
  - 工具调用展示参数、命令、输出、错误和状态。
  - 展示消息时间、模型、耗时、token、费用等元信息。
  - 支持深浅主题、可拖拽调整的侧栏和会话深链。

- **三层搜索**
  - **目录搜索**：按会话标题、目录、slug、会话 ID、Agent、模型过滤左侧目录树。
  - **全局搜索**：检索所有会话的消息、思考过程、工具参数与输出，以及标题、目录、ID、模型等元数据。
  - **当前会话搜索**：在右侧对话中查找，支持逐个跳转，并自动展开匹配所在的折叠块。

- **全局搜索定位**
  - 结果按会话分组，显示匹配片段数量和高亮摘要。
  - 点击摘要可直接打开对应会话，并定位到具体消息或工具调用位置。
  - 结果较多时最多展示前 60 个会话，并给出提示。

## 环境要求

- Node.js **22.5 或更高版本**（使用内置的 `node:sqlite`）。
- 不需要安装任何 npm 运行时依赖。

默认数据库路径：

```text
~/.local/share/opencode/opencode.db
```

## 快速开始

```bash
cd opencode-reader
npm start
```

打开：

```text
http://127.0.0.1:4173
```

项目没有第三方 npm 运行时依赖，因此不需要执行 `npm install`。

### 自定义数据库或端口

```bash
OPENCODE_DB=/path/to/opencode.db PORT=8080 npm start
```

可用环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OPENCODE_DB` | `~/.local/share/opencode/opencode.db` | OpenCode 数据库路径 |
| `PORT` | `4173` | HTTP 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址；改成 `0.0.0.0` 会允许局域网访问 |

> 默认只监听本机，避免把会话内容暴露到网络中。

## 使用说明

### 左侧目录

1. 在“目录”标签下输入关键词，会即时过滤会话树。
2. 搜索范围包括会话标题、目录路径、slug、会话 ID、Agent 和模型。
3. 按 `Enter` 会打开第一个匹配的会话。
4. 点击会话后，右侧加载完整对话。

### 左侧全局搜索

1. 切换到“全局搜索”标签，或按 `Ctrl+Shift+F`。
2. 输入关键词后会自动搜索整个数据库。
3. 结果中的“思考 / 助手 / 你 / bash / read”等标签表示匹配内容所在的位置。
4. 点击任意摘要可直接跳转到对应消息或工具输出。
5. 点击会话标题只打开会话，不定位具体片段。

全局搜索会优先展示消息正文和思考过程中的匹配，再展示工具调用中的匹配。

### 右侧会话搜索

1. 会话加载后，顶部会出现搜索框。
2. 支持搜索对话正文、思考过程、工具参数和工具输出。
3. 按 `Enter` 跳到下一个，`Shift+Enter` 跳到上一个。
4. 如果匹配位于折叠的思考过程或工具调用中，会自动展开。
5. 匹配数量超过 3000 时显示为 `3000+`。

## 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl+K` / `Cmd+K` | 有会话时聚焦右侧搜索，否则聚焦左侧搜索 |
| `Ctrl+Shift+F` | 切换到全局搜索 |
| `/` | 聚焦左侧搜索框 |
| `Enter` | 目录模式打开首个会话；全局模式打开首个结果；会话搜索跳到下一个 |
| `Shift+Enter` | 会话搜索跳到上一个 |
| `Esc` | 清空当前搜索框 |
| 拖拽侧栏分隔条 | 调整左右宽度（聚焦分隔条后也可用方向键） |

## 数据来源与实现

服务端通过 `node:sqlite` 以只读模式打开 OpenCode 数据库：

```sql
PRAGMA busy_timeout = 5000;
PRAGMA query_only = ON;
```

主要读取以下表：

- `session`：会话标题、目录、模型、时间、token、费用等。
- `message`：消息角色、模型、耗时、错误等。
- `part`：消息正文、思考过程、工具调用、压缩标记等。

数据库使用 WAL 模式时，可以在 OpenCode 正在运行的情况下读取最新数据。点击右上角“刷新”会重新读取会话列表和当前会话。

### 搜索实现

- 目录搜索在前端对会话元数据做子串匹配。
- 全局搜索在后端使用 SQLite `json_extract` + `instr(lower(...))`，只检索实际内容字段：
  - 消息正文 `$.text`
  - 思考过程 `$.text`
  - 工具名称 `$.tool`
  - 工具标题 `$.state.title`
  - 工具参数 `$.state.input`
  - 工具输出 `$.state.output`
  - 工具错误 `$.state.error`
- 服务端生成匹配片段，并对每个会话返回最多 4 条摘要。
- 全库结果按会话最后更新时间排序，最多返回前 60 个内容匹配会话。

### Markdown 与安全

- 使用 `marked` 将 Markdown 转换成 HTML。
- 使用 `DOMPurify` 清洗生成的 HTML，阻止脚本、事件属性和危险链接。
- 消息、工具输出、目录名等插入 DOM 前都会进行 HTML 转义。

## HTTP API

| 接口 | 说明 |
| --- | --- |
| `GET /api/tree` | 返回数据库路径和全部会话元数据 |
| `GET /api/session/:id` | 返回指定会话及其消息、消息片段 |
| `GET /api/search?q=关键词` | 全库内容搜索，返回按会话分组的匹配片段 |

## 已知限制

- 全局搜索最多返回前 60 个内容匹配会话；关键词过于宽泛时建议缩小范围。
- 全局搜索需要扫描 `part` 表，数据量很大时单次查询可能需要数百毫秒。
- 极大的工具输出会完整保留在 DOM 中，便于搜索，但会占用更多内存。
- 项目依赖当前 OpenCode 数据库表结构；OpenCode 修改 schema 后可能需要适配。
- 仅支持读取，不提供编辑、删除或导出会话功能。
